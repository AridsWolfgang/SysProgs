From a C library call to a system call

Understand what happens when a program asks the operating system to do work — and why the distinction matters when you debug real software.

Beginner25 minutesSystems foundations● Lesson in progress
The central idea

A library function and a system call are not the same thing. A library function may prepare, buffer or transform work before invoking an operating-system interface.

The three layers

A typical hosted C program runs in user space. It can call library functions such as printf. The C library may format text and buffer output. When data must be sent to a file descriptor, the library can invoke the operating system's write interface. The kernel performs the privileged operation.

→

→

→

A simplified path. Actual library behaviour depends on the runtime, stream state and operating system.

Compare two ways to write output

library-vs-system-interface.c
#include <stdio.h>
#include <unistd.h>

int main(void) {
    printf("Hello from the C library\n");
    write(STDOUT_FILENO, "Hello from write\n", 18);
    return 0;
}

printf formats output through the C standard I/O library. write is a POSIX interface that requests writing bytes to a file descriptor. This example is POSIX-oriented and is not directly portable to every operating system.

Watch for buffering

The order in which output appears can depend on buffering and whether streams are connected to a terminal or redirected. Flush stdout or run the calls separately when you need a controlled tracing experiment.
