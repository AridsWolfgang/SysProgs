## Story — Kitchen vs Waiter

**Library (waiter):** You say `printf("hello %d", 42)`. The waiter (C library) formats `"hello 42\n"` into a buffer, decides when to flush, handles `errno`, retries on `EINTR`. You don't think.

**Syscall (kitchen):** You say `write(1, "hello 42\n", 9)`. You are in the kitchen. You choose fd `1`, buffer, length. No formatting, no buffering, no retry — you handle `9` vs `-1` and `errno` yourself.

```c
// HIGH — buffered, portable, formatted
printf("hello %d\n", 42); // → fwrite → write

// LOW — raw, unbuffered, exact
write(1, "hello 42\n", 9); // 9 bytes, no format, no buffer
```

Why two paths? **Control vs convenience.** 99% of apps want convenience (`FILE*`). Databases, games, browsers want control: huge files, low latency, zero-copy (`sendfile` needs raw fd, not `FILE*`).

## The Trap — Per Arch

| Arch | Trap | Sysno reg | Args | Ret |
|------|------|-----------|------|-----|
| x86-64 Linux | `syscall` | `rax` | `rdi rsi rdx r10 r8 r9` | `rax` |
| x86 32 | `int 0x80` | `eax` | `ebx ecx edx` | `eax` |
| ARM A64 | `svc #0` | `x8` | `x0-x5` | `x0` |
| RISC-V | `ecall` | `a7` | `a0-a5` | `a0` |

On Windows, no `syscall` for you — `WriteFile` → `NtWriteFile` via `ntdll`. Same idea, different numbers.

## Try — strace Is Truth

```bash
# Linux / WSL
gcc modules/00-orientation/examples/00-hello-c.c -o hello_c && strace -e write ./hello_c 2>&1 | head
# write(1, "[LOW ] Hello via write(fd=1)\n", 27) = 27
# write(1, "[HIGH] Hello via printf...\n", 34) = 34

# Windows — Procmon (Sysinternals) filter WriteFile, or just reason: _write → WriteFile → NtWriteFile
```

Change `1` → `2` in `write(1,…)` → output moves from stdout to stderr. `2>` redirect now captures it. That's fd semantics, not magic.

## Lab (Lecture)

1.  Open `00-hello-c.c`, comment `printf`, keep `_write`/`write`, recompile — still prints. Now you believe.
2.  Change `1` to `2`, run `./hello_c 2>err.txt; cat err.txt` — see it.
3.  (Linux) `strace -c ./hello_c` — count `write` calls: 2 vs `printf`-only 1? Buffering merges.
